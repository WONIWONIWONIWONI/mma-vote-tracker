# 구조 검토와 정리 — 2026-10-20

## 적용한 정리

1. 대회 정보·종료 시각·팀 색상·예측 대상이 여러 JS/Python 파일에 중복돼 있었다. `tracker.config.json`으로 모으고, 생성된 브라우저 설정과 원본이 다르면 테스트가 실패하게 했다. 현재 MMA의 한글 설명/HTML은 전용 화면으로 남긴다. 다음 대회는 전용 문구까지 복사하지 않고 새 생성기를 사용한다.
2. 최신 이력과 예측 장부가 각각 timeout/Contents API/raw fallback을 구현했다. `http.js`가 한 방식으로 처리한다. 응답의 구조 검증 실패도 fallback 사유다. 라이브 조회와 과거 이력 조회의 독립 실행, 마지막 정상값 보호는 유지했다.
3. 삭제된 직전 관측 패널의 이미지 모델·그리기 함수, 이전 시간별 레이아웃 CSS, 사용하지 않는 상태와 도달 불가능한 주 차트 표차 분기를 제거했다. 캔들 스타일은 JS 문자열 주입에서 `candles.css`로 이동했다.
4. 날짜마다 전체 관측을 다시 찾던 일별 집계를 단일 버킷 구성으로 바꿨다. 정렬 이후 날짜 경계 검색은 관측 수+날짜 수에 비례한다. 첫날 역산·자정 누락·정정 처리 기준은 그대로다.
5. 누적 과거 예측의 각 구간마다 실제값 추출/정렬을 반복하던 처리를 한 번으로 줄였다. 차트에서 같은 데이터의 실제값도 캐시한다. 경로·학습·모델 선택 기준은 변경하지 않는다.
6. 브라우저는 모델 자동 선택 계산 코드 대신 가벼운 후보 설명 목록만 로드한다. 선택기는 수집 서버에서 실행한다.
7. 사람이 읽을 수 있도록 소스 포맷을 정리하고 `package-lock.json`으로 개발/검증 도구 버전을 고정했다. 배포에 새 프레임워크나 런타임 의존성을 추가하지 않았다.
8. 중복된 시기별 README 설명은 변경 이력으로 옮겼다. 현재 기능, 설정, 운영, 새 대회 연결을 분리했다.

## 유지한 것과 이유

- `dist/data/`의 실제 관측과 고정 예측은 수정하지 않는다. 정리 작업으로 기존 예측이 사라지거나 재학습되는 일은 없다.
- `collector/legacy/`는 사용하지 않는 쓰레기 코드가 아니다. 이전 예측 여섯 개의 재현 근거이므로 고정 보존한다.
- `top4`는 이미 배포된 JSON의 호환 필드다. 이름만 더 예쁘게 바꾸려고 전체 기록을 마이그레이션하지 않는다.
- 현행 상세 화면과 다중 투표처 화면을 억지로 하나의 거대한 옵션 분기로 합치지 않는다. 검증·조회·일별 계산·축·합산 같은 실제 공통 기능을 공유하고 화면은 목적에 맞춰 분리한다.
- 현재 모델을 다른 대회에 자동 적용하지 않는다. 새 대회의 기간, 표수 분포와 패턴을 검증한 뒤 예측 대상/학습을 정한다.

## 다중 원본 데이터 계약

각 원본의 관측은 `{sourceId, observedAt, sourceAt, totalVotes, candidates}`다. `observedAt`은 성공한 조회 시각, `sourceAt`은 원본이 실제로 제공한 집계 시각이며 없으면 null이다. 후보는 원본 ID·이름·정수 표수를 가진다. 한 원본 응답의 전체 후보 합계가 분모가 된다. 현재 UI 표시 대상 후보만으로 전체 투표수를 계산하지 않는다.

설정의 `candidateIds`는 공통 후보 ID→원본 후보 ID다. 순위나 표시 이름으로 서로 다른 플랫폼의 팀을 추정 매칭하지 않는다. 관심 후보 모두의 원본 ID를 명시한다. 원본에 후보가 없으면 0표가 아닌 불완전한 관측이다.

합산은 **공개 표수 단순 합**만 지원한다. 각 원본의 득표율을 더하지 않는다. 합산 비율은 합산 후보 표수 / 모든 원본의 전체 후보 표수다. 정수 범위 초과, 중복 후보, 잘린 목록, 잘못된 합계는 거절한다. 공식 가중 점수가 필요하면 규칙을 확인하고 별도 계산/표시를 추가한다.

양쪽 원본은 동시에 요청하지만 응답 시각이 완전히 같다고 가정하지 않는다. 설정한 유효 기간과 원본간 최대 시각차를 통과할 때만 합계가 유효하다. 원본 집계 시각이 있으면 신선도·시각차 판단에 반영한다. 시각 미제공 원본은 조회 시각으로만 판정하므로 실제 서버 집계 지연을 알아낼 수는 없다. 실패 원본의 마지막 관측은 남기되 유효성에 따라 합계를 보류한다.

시계열은 시간순 한 번의 순회로 각 시점까지 도착한 관측만 사용한다. 미래 응답으로 과거 합계를 채우지 않는다. 원본별·분별 가장 최신 관측 하나를 유지하며 표수 정정은 허용한다. 빈 구간은 차트에서 끊는다. 날짜별 계산은 공통 `daily.js`에 정상 관측만 넘긴다.

## 운영 범위

기존 사이트의 장기 실행/교대 수집기는 유지했다. 새 프로젝트 생성물은 독립 원본 수집과 5분 Actions 예약을 기본으로 제공한다. Actions의 정시 실행은 보장되지 않는다. 더 엄격한 수집 SLA가 필요하면 동일한 수집 함수를 상시 실행 환경에서 호출하고 저장소 읽기 API로 교체할 수 있다. 페이지 새로고침은 원본 CORS가 허용할 때 서버 보관 지연과 독립적으로 최신값을 읽는다.

이력은 아직 JSON 단일 파일이다. 현재 대회의 규모에서는 단순성과 감사 가능성이 유리하지만 장기·다수 대회에서는 원본/날짜별 분할 파일 또는 DB를 도입해야 한다. 이번 정리에서 불필요한 DB·번들러·로그인 체계는 추가하지 않았다.
