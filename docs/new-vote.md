# 다음 투표를 링크에서 새 트래커로 만드는 절차

사용자는 투표 링크만 제공해도 된다. 아래 조사와 설정 작성은 작업을 맡은 에이전트가 수행한다. 사용자가 API URL이나 후보 ID를 직접 알아낼 필요는 없다. 접근 불가·비공개 집계 등 실제 막힘이 있을 때만 필요한 사항을 묻는다.

## 1. 공식 링크와 규칙 확인

- 제공된 투표 페이지, 공식 안내, 투표 기간, 공개 집계 지표를 확인한다.
- 멜론 글로벌 MMA TOP10과 베리즈가 같은 후보·기간·단위로 집계되는지 확인한다. 중복 집계인지 독립 투표처인지 확인하지 않고 더하지 않는다.
- 표수 합, 플랫폼별 비율, 가중 공식 점수는 구분한다. 공식 점수 규칙이 다르면 원시 표수 합계를 ‘공식 순위’라고 부르지 않는다.
- 공개 읽기 API가 있는지, 응답이 전체 후보 목록인지, 페이지네이션·반올림·집계 시각·CORS 여부를 확인한다. URL의 연도나 경로를 추측해 연결하지 않는다.
- 공개 응답을 읽는 것만 수행한다. 투표 제출·계정 인증·비공개 API 우회는 이 템플릿의 기능이 아니다.

## 2. 설정/어댑터 작성

`qa/fixtures/multi-config.json`은 **검증용 가상 원본**이다. 다음 설정의 형태만 참고하고 `.example` 주소나 팀 ID를 실제 프로젝트에 쓰지 않는다.

| 설정                        | 작성 기준                                                                       |
| --------------------------- | ------------------------------------------------------------------------------- |
| `id`, `title`, `repository` | 새 대회와 새 저장소. 기존 MMA 저장소 재사용 금지                                |
| `startsOn`, `endsAt`        | 확인한 공식 기간과 마지막 수집 여유. KST 경계                                   |
| `sources[].url`             | 공식 투표 페이지                                                                |
| `sources[].endpoint`        | 직접 확인한 공개 집계 경로. 비밀값을 설정에 넣지 않음                           |
| `sources[].adapter`         | 확인된 멜론 구조는 `melon-top10`, 다른 공개 JSON은 `mapped-json` 또는 새 어댑터 |
| `sources[].fields`          | 공개 JSON의 rows/id/name/votes/선택적 total/share/status/sourceAt 경로          |
| `sources[].fullRoster`      | mapped-json이 전체 후보를 제공함을 확인한 경우만 true                           |
| `sources[].candidateIds`    | 공통 후보 ID별 해당 원본 ID. 순위/이름 자동 매칭 금지                           |
| `candidates`                | 관심 팀의 공통 ID/이름/색상. 모든 원본에 각각 매핑                              |
| `aggregation`               | `mode: sum-votes`, 확인한 업데이트 주기에 맞는 maxSkewSeconds/staleAfterSeconds |

새 원본 형식은 `dist/sources.js`에 추가한다. 어댑터는 공통 관측 계약으로만 반환하고 합산·화면을 수정할 필요가 없게 한다. 전체 후보가 여러 페이지면 모든 페이지를 일관되게 확보한 뒤 하나의 관측으로 반환한다. 표수 없이 비율만 있으면 표수를 만들어내지 말고 별도 지표 방식으로 설계한다.

## 3. 빈 새 프로젝트 생성

```sh
node scripts/new-tracker.cjs --config /path/confirmed-vote.json --out /empty/new-vote-tracker
```

- 기존 폴더가 비어 있지 않으면 거절한다.
- 현재 대회의 `dist/data/`, 예측 장부, legacy 복원 모델을 복사하지 않는다.
- `dist/config.js`, 새 모바일 대응 화면, 수집기, 빈 `multi-history.json`, Pages/수집 워크플로를 생성한다.
- 첫 화면은 합계. **합계 / 멜론 / 베리즈** 전환과 투표처 기여분을 우선한다. 그래프를 원본 수만큼 세로로 복제하지 않는다.
- 원본 연결 후 초기 실제 관측을 수집한다. 관측 전에는 ‘기록 대기’를 표시하고 예시 수치를 배포하지 않는다.

## 4. 검증과 배포

1. 원본 응답 fixture로 표수·전체 분모·후보 매핑을 검증한다.
2. 양쪽 성공, 한쪽 실패/지연, 관측 시각차, 후보 누락, 0표, 정정, 중복, 날짜 경계를 검사한다.
3. 합계·원본 탭·기여분·모바일 가독성·차트 확대/이동을 검증한다.
4. 새 GitHub 저장소를 만들고 Pages의 Actions 배포를 설정한다. 최초 수집과 배포를 실행한다. 생성물은 설정 가능한 운영 출발점이며 GitHub 저장소/Pages 설정까지 자동 권한을 가정하지 않는다.
5. 실제 사이트에서 최신값과 출처별 시각을 확인한다. 이후 링크만 전달하면 이 절차를 이어간다.

기존 상세 캔들/예측 패널이 필요하면 새 대회의 대상 팀·단위·충분한 학습 기간을 확인한 후 공통 모델/패널을 연결한다. 이전 대회의 학습값이나 과거 예측을 이어 붙이지 않는다. 생성기는 기본적으로 합계/원본 순위·추이·일별 비교에 집중한다.
