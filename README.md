## 확대·이동과 이력 동기화 보완

- 멜론 최신 조회 버튼은 과거 이력 응답을 기다리지 않고 다시 사용할 수 있습니다. 진행 중인 이력 요청은 하나만 유지합니다.
- 공용 이력은 GitHub Contents API를 먼저 읽고 제한·실패 시 raw 주소로 대체합니다. 늦게 도착한 이력이 최신 직접 관측을 덮어쓰지 않습니다. 이력 마지막 시각도 지연 시 별도로 표시합니다.
- 득표수/점유율이나 기간을 바꿔도 확대 기준 팀을 다시 중심에 놓습니다. 확대 배율에 관계없이 그래프를 좌우·상하·대각선으로 드래그해 이동합니다. 휠은 커서 주변 두 축을 확대하고, 모바일 핀치는 두 손가락의 중간점을 유지합니다.
- 캔들 차트는 실제 그리기 영역과 커서/두 손가락 중간점을 기준으로 확대합니다. 핀치 시작 시점의 관측 위치를 유지하며 여러 번 움직여도 확대 중심이 누적 이동하지 않습니다.
- 캔들을 차트 폭 전체에 표시하고 PC 마우스 드래그, 확대·축소·전체 보기 버튼을 추가했습니다.
- 배포 전 `qa/test_ui.cjs`로 PC/모바일 실제 입력, 늦은 이력, 자동 요청 없음, 팀 색상, 양수/음수 격차 방향을 검사합니다. 배포 후 `qa/live_probe.cjs`로 실제 사이트에서 멜론 직접 조회와 세로 드래그를 확인합니다.

분석: 10월 15일 20:00~21:28 KST 보관 기록에는 2분 초과 수집 공백이 없었습니다. 수 분의 과거 기록이 한꺼번에 보인 현상은 원본 수집 간격만으로 설명되지 않으며 이력 전달 경로의 캐시·배포 지연과 구분해야 합니다. 이전 실행 로그에는 10초마다 수집·커밋한 기록이 있었고, 21:28 KST 확인 당시 60초 간격이었습니다. 단발 예약 수집은 예약 시작 지연이 확인되어, 2시간 유지되는 수집기 내부의 5분 주기로 변경했습니다. GitHub Actions 예약 실행은 시작 지연을 보장할 수 없으므로 최신값을 멜론에서 직접 읽어 이력 전달 지연의 영향을 줄입니다. 공용 이력도 실시간 보장이 필요하면 상시 수집 서버·DB·짧은 캐시의 읽기 API로 이전하는 것이 후속 방안입니다.

- Ctrl+휠 확대·축소를 반복해도 양 끝 캔들 여백은 7px로 고정하고, SVG 밖으로 그려진 요소가 페이지 폭을 늘리지 않도록 제한합니다. 수집 커밋이 겹칠 때 JSON을 관측 시각별로 병합해 저장 충돌로 수집이 중단되는 문제도 처리합니다.

## 예약 지연을 수집 주기와 분리

5분마다 새 Actions 실행을 기다리는 방식에서는 예약이 늦으면 관측 자체가 멈춥니다. 2026-10-15 22:10 KST 확인 시 마지막 저장은 22:01:22였고 다음 예약 실행이 생성되지 않았습니다. 현재는 단일 수집기가 최대 2시간 동안 5분 간격을 직접 지킵니다. 반시간 예약은 다음 수집기를 대기시키며, 동시 실행 제한으로 수집기가 겹치지 않도록 합니다. 조회·저장 실패는 다음 주기에 재시도하고 실제로 관측한 값만 보존합니다. GitHub가 실행 자체를 제공하지 않는 상황이나 수집기 교대 때까지 정확한 시각을 보장하지는 못합니다.

## 교대·자동 복구 알고리즘

1. 시작한 수집기가 GitHub API로 다음 수집기를 요청하고 실제 대기열 등록을 확인합니다. 이미 예약된 수집기가 있으면 중복 요청하지 않습니다.
2. 2시간 교대 시각에 대기열을 다시 확인합니다. 후속 수집기가 확인되지 않으면 기존 수집기가 최대 2시간 더 수집합니다. 교대 직전에 실제 관측을 저장하고 대기 중인 수집기로 넘깁니다.
3. 조회·저장 실패는 15→30→60→120초 간격으로 재시도하고 성공하면 5분 주기로 돌아갑니다. Git 작업과 GitHub 요청에는 시간 제한을 둡니다. 여러 미전송 커밋의 충돌도 실제 관측 시각별로 병합합니다.
4. 수집 작업이 끝나면 별도 복구 작업이 후속 실행을 확인합니다. 실행이 없으면 자동 시작하고, 15분 넘게 상태 기록이 갱신되지 않은 오래된 작업은 취소 후 교체합니다. 원본 조회 오류라도 상태 기록이 새로 갱신되면 정상 생존으로 구분합니다.
5. 15분 예약 감시를 보조로 사용합니다. 10분 안에 시작 실패가 3회 이상 반복되면 재시작 폭주를 막고 다음 감시 때 다시 확인합니다. 투표 종료 시각 이후에는 후속 작업을 만들지 않습니다.

GitHub Actions 전체 장애나 실행 자원 부족까지 이 저장소 코드로 없앨 수는 없습니다. 정상 운영에서는 예약 시작 시각에 의존하지 않고 후속 실행 대기열을 미리 준비합니다.

## 날짜별 증가량
시간에 따른 변화 상단에 KST 00시 기준 하루 누적 증가량을 표시합니다. 팀별 증가량 순 정렬과 최다 증가 강조, 전체 후보 증가량, 지난 날짜별 마감표를 제공합니다. 직접 조회와 과거 이력 동기화 시 함께 갱신합니다. 자정은 새 날짜로 전환하지만 원본 요청은 기존처럼 수동 새로고침 방식입니다.
정확한 자정 관측이 있으면 전날 마감값과 다음날 시작값을 공유합니다. 첫날 또는 경계 관측이 누락된 날짜는 실제 첫/끝 관측 차이만 표시하고 일부 구간으로 구분합니다. 없는 팀의 기준값은 0으로 가정하지 않습니다. 과거 이력의 추가 동기화는 마감표에도 반영됩니다.
검증: `node qa/test_daily.cjs` (자정 경계, 순위 변경, 첫날, 누락, 새 날짜 전환, 정정).
